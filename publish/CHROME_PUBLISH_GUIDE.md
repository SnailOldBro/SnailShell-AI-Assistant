## 0. 先看差异：Chrome 和 Edge 不一样

你刚走完 Edge 流程，Chrome 有几处**关键不同**，先记住能省很多时间：

| 项目 | Edge | Chrome | 备注 |
|---|---|---|---|
| 注册费 | 免费 | **一次性 $5** | Google 收，终身不续费 |
| 两步验证 | 不强制 | **必须** | 没开 2FA 进不了后台 |
| 商店图标 | **300×300** | **128×128** | 我们的 `icons/icon128.png` 正好 128×128 ✅ |
| 促销图 | 440×280 / 1400×560 | 440×280 / 1400×560 | 相同，已做好 |
| 可见性 | Public / Hidden | **Public / Unlisted / Private** | `Hidden` 在 Chrome 叫 **Unlisted** |
| 远程代码声明 | **有**（选否+澄清） | **没有这一项** | Edge 特有，Chrome 少一步 |
| **审核时长** | 3–7 工作日 | **可能 1–3 周** | ⚠️ 关键差异，见第 6 节 |
| 审核方式 | 人工细审 | **按权限分级** | `<all_urls>` 属最高风险级 |
| 新账号槽位 | 无明确限制 | **默认仅 2 个** | 2026-08-20 新政策 |

## 1. 前置条件（按顺序做）

### ① 准备一个专用 Google 账号

- **不要用你的个人 Gmail**。这个账号的邮箱地址**注册后永久不可更改**，一旦用来发扩展，商店主页就绑死了
- 建议单独注册一个 Gmail，名字与品牌一致（例如 `snailshell.ai.assistant@gmail.com`）
- 需要能长期收信（审核通知、验证邮件）

### ② 开启两步验证（2SV）

后台强制要求。没开会在注册时报错。

设置 → 安全性 → 两步验证 → 绑定手机或验证器 App。

### ③ 支付 $5 注册费

- 只能刷**信用卡 / 借记卡**（不支持支付宝、微信、银联）
- **一次性**，之后上架这个扩展、以及以后所有扩展都不再收
- 付款需要 Google 账号 + 开发者资料

### ④ 确认开发者资料

- 姓名、公开邮箱、公开网站
- 用途：留一个能打开的页面（可以直接用你的 GitHub 仓库：<https://github.com/SnailOldBro/SnailShell-AI-Assistant>）

## 3. 上传与提交步骤

### Step 1 — 打开开发者后台

<https://chrome.google.com/webstore/devconsole>

首次进入会让你同意开发者协议 → 选国家/地区 → 付款。

### Step 2 — 新建扩展

左上角 **Add new extension 新增扩展** → 第一次会让你先填开发者资料 → **Upload a zip file 上传 zip 包**

选择桌面的 `00-扩展安装包-snailshell-v1.2.4.zip`

> 2026 年起，上传草稿时 Google 会**立即跑一次自动安装检测**，装不上的包会被当场标记。所以如果这里报错，回头看包的问题。

### Step 3 — 商店列表（Store listing）

> 💡 **与 Edge 的重要差别**：Chrome 的 **Name 字段是可编辑的**（Edge 是只读取自 manifest）。
> 所以这里可以把中英文名都放进去，两拨用户都能搜到。

**建议填写：**

| 字段 | 中文页 | 英文页 |
|---|---|---|
| 名称 Name（≤75） | `蜗牛壳AI助理 SnailShell AI Assistant` | 同左（32 字符，两边都能搜） |
| 简短说明 Summary（≤132） | `用你自己的 API Key 直连自定义 AI 模型，一键总结网页、追问要点、右键引用提问。数据不经任何中转。` | `Summarize pages, ask questions, and quote selections with your own OpenAI-compatible model and API key. No relay server.` |
| 详细说明（≤5000） | 用 `EDGE_STORE_LISTING_FILL.md` 的中文长描述 | 用同文件末尾的英文长描述 |

- **图标 Icon**：128×128（`icons/icon128.png`）
- **截图 Screenshots**：1–5 张，建议 4 张全传，第 1 张是总结场景
- **小/大促销图**：可选，440×280 / 1400×560
- **分类 Category**：选 `Productivity（生产力）`
- **语言**：填完中文后点 **Add language** 加 `English (United States)`，素材用 `英文版/` 的

> ⚠️ 描述用词注意：2026-08-01 新政策**禁止**「绕过 AI 平台安全保护 / 使用限制」的扩展。
> 正面表述为「自定义模型 / 自带 API Key / OpenAI 兼容」，**不要**出现「破解 / 绕过 / 解除限制 / 破解版」等词。

### Step 4 — 隐私实践（Privacy practices）⭐ 细审重点

逐项文案见 **`CHROME_PRIVACY_FORM_FILL.md`**，可直接复制。要点：

- 隐私政策 URL（已部署）
- 单一用途声明
- 7 条权限逐条合理化
- 数据使用：**全部不勾**（不收集）
- 两条合规声明勾选

> Chrome **没有**「远程代码」这一项（Edge 才有），所以比 Edge 少一步。

### Step 5 — 分发（Distribution）

- **可见性 Visibility**：
  - `Public` 可搜索可安装 → **正式发布选这个**
  - `Unlisted` 只能通过链接安装，不出现在搜索 → 想先低调测试选这个
  - `Private` 仅指定账号
- **地区**：默认全部。若不想在某些地区出现可取消勾选。
- **商家身份 Trader status**（EU DSA 要求）：个人免费工具选 **`Non-trader（非商家）`**
  - ⚠️ 选 Trader 会要求公开**实体地址和电话**，选 Non-trader 就不需要

### Step 6 — 提交审核

页面顶部出现 **Submit for review 提交审核** 按钮 → 点击 → 状态变 **Under review**。

## 4. 审核时长与分级（重点）

Google 2026 年按权限风险分级：

| 级别 | 权限组合 | 审核方式 | 时长 |
|---|---|---|---|
| Level 1 | `storage` `activeTab` | 自动 | 几小时–2 天 |
| Level 2 | `scripting` `contextMenus` | 自动/半人工 | 2–5 天 |
| **Level 3** | **`host_permissions: <all_urls>`** `tabs` `cookies` | **人工逐行看代码** | **1–3 周** |

**我们的扩展有 `<all_urls>` → Level 3 → 人工审核，1–3 周。**

这是和 Edge 最大的不同（Edge 3–7 天）。请做好心理准备，别以为被拒了。

### ⚠️ 绝对不要重复提交刷队列

重新提交会**重置审核计时**，还可能给账号打上风险标记。提交后就等，别动它。

## 5. 最大风险：审核员可能无法测试 AI 功能

**问题**：Chrome 没有 Edge 那种「Notes for certification（认证说明）」字段，你没法在审核材料里塞一个测试 API Key。而没有 Key，扩展就是个空壳——审核员点「总结本页」毫无反应。

**这是可能被拒的头号原因。**

### 三种应对方案

**方案 A（推荐）：在描述里写清自助路径**

在详细说明末尾保留这段（已有）：

> 支持自定义 OpenAI 兼容模型（DeepSeek / Qwen / GLM / Kimi / Ollama / 任意 endpoint），用你自己的 API Key 直连

审核员看到这句话会明白「需要用户自备 Key」是设计如此，不是故障。**隐私优先类 AI 扩展大量走这条路，通常能过。**

**方案 B：做一个无需 Key 的降级演示模式**

加一个内置的假数据演示模式（比如首次打开时有个示例回答）。能显著提高过审率，但要改代码，且要保证不误导（不能让人以为是真 AI 输出）。

**方案 C：提交后如果被拒，直接按意见重提**

Edge 可以直提，Chrome 也一样。被拒后按意见改完重新提交即可，不用重新排队。

## 6. 2026 年新政策（务必知道）

**2026 年 8 月 1 日起生效的 Chrome 商店政策更新**：

1. **数据收集收紧**：只能收集与功能直接必需的信息；与核心用途无关的收集一律违规
2. **透明度要求**：即使是「较小」的数据类型也必须披露
3. **事后变更须告知**：安装后若改变数据处理方式，必须主动告知用户
4. **AI 相关新规**：**禁止**专门用于绕过 AI 平台安全保护、使用限制或其他防护措施的扩展
5. **强制下架**：此后发现不合规的扩展可能被下架

> 第 4 条与我们有关：我们的扩展是「让用户用自己的 Key 连接自己选的模型」，**不绕过任何 AI 平台的限制**。
> 但**描述用词要小心**——不要出现「破解」「解除限制」「绕过」这类词，正面表述为「自定义模型 / 自带 Key」。

另外：**Manifest V2 已于 2026-08-31 从商店彻底移除**。我们是 MV3，不受影响。

## 7. 常见被拒原因与规避

| 被拒原因 | 怎么规避 |
|---|---|
| 申请的权限用不上 | 只申请真正用到的，每条都写清理由 |
| 权限申请过宽 | `<all_urls>` 必须写「仅用户主动触发、只读已渲染文本、不碰 Cookie/凭据/历史」 |
| 描述与实际不符 | 截图展示的必须是真的能用的功能 |
| 缺隐私政策 | URL 必须能公开访问 |
| 功能太少/太简单 | 描述里把三个核心功能都讲清楚 |
| 误导性安装诱导 | 不能在描述里写「免费」却收费，也不能诱导跳转付费 |
| 商店信息不完整 | Logo/截图/描述/分类一个都不能空 |

> ⚠️ 关于「鼓励支持」收款码：属于自愿赞助，Chrome 政策允许，但**不要在描述里强调收费、付费、购买**这类词，避免被判定为诱导或商业误导。功能本身不收取任何费用即可。
